# 账号表情包导出与导入 —— 踩点与设计

> **一句话**：NapCat 能拿到账号「收藏表情」的直链（实测 25 张），可以把它们做成
> `meme_manager` 的本地表情包；官方包已卸载并备份，选图改由情感辅助模型负责。

状态：**已实施**（2026-10-26）。官方包已卸载；账号收藏 25 张已做成 `qq-fav-001`；
情感辅助模型因每轮多出 20–27 秒已关闭，改由 `qqbotstack_memechance` 按概率随机配图。

---

## 0. 结论

**可行。** 有两条独立通道：

1. **OneBot 动作（推荐）**：NapCat 暴露 `fetch_custom_face` 与 `fetch_custom_face_detail`。
   前者返回收藏表情的 URL 数组，后者返回 `emojiInfoList`（`resId`、`md5`、`url`、`emoPath`、
   `desc`、`isAPNG`）。实测账号共有 **25 张**收藏：3 GIF、2 PNG、20 JPG。
2. **本地缓存（兜底）**：QQ 数据目录下 `nt_data/Emoji/personal_emoji` 有同名缓存文件；
   另外 `emoji-recv` 是群聊里收到过的表情缓存（114 个文件），`marketface` 是聊天里用过的
   商城表情（3 个），它们不是「收藏列表」，只能当补充素材。

官方包与本方案的取舍：官方包 402 张、19 个分类，但画风与人设不符；账号收藏只有 25 张，
数量少，但都是你自己攒的，画风统一（一套小狗表情 + 少量照片/猫图）。

---

## 1. 现状与已完成的改动

### 1.1 为什么之前完全不出图

`meme_manager` 的旧版「分类标记」模式要求**回复模型自己**在正文里输出 `&&分类键&&`。
实测：同一套人格 + 世界书 + 表情提示词，

- 不带工具定义时，`HY3-Free` 会正常输出标记；
- 带上真实工具集（解析、点歌、群历史）后，6 条只出 1 条；
- `Beam` 即使不带工具也 0/4。

线上日志里 34 条回复全部解析到空列表，根因就是回复模型不配合标记协议，与表情包内容无关。

### 1.2 已完成的改动

| 改动 | 结果 |
|---|---|
| 卸载 `official-001` | 包目录已删除；卸载前完整复制到插件数据目录的 `backup/` 下 |
| 新建 `qq-fav-001` | 25 张账号收藏，10 个分类；`registry` 登记、`selection_rules` 设为默认 |
| 开启情感辅助模型（后关闭） | 先验证了 `emotion.llm.enabled=true` 可用，但每轮多一次模型往返（实测 20–27 秒），已关闭 |
| 关闭旧标记模式 | `generation.emotion.probability=0`，避免模型偶尔输出 `&&分类&&` 时再配一张 |
| 新增随机配图插件 | `qqbotstack_memechance`：按概率从 `qq-fav-001` 随机选一张，见 §3.5 |
| 导出收藏表情 | 25 张原图已下载留存，供选图与分类使用 |

开启情感辅助模型后，插件不再依赖回复正文：每轮单独发一次选图请求，返回
`{"emotions":["分类键"]}`，再由插件从对应分类随机取图。用 `HY3-Free` 实测这组提示词可
正常返回有效分类。

## 2. 导出通道（已验证）

### 2.1 动作与返回

```text
fetch_custom_face        { count }  -> ["https://.../0", ...]
fetch_custom_face_detail { count }  -> [{ resId, md5, url, emoPath, desc, isAPNG, ... }]
```

- `count` 默认 48，可传更大值；返回顺序与收藏顺序一致。
- URL 形如 `https://p.qpic.cn/qq_expression/<uin>/<resId>/0`，可直接下载。
- `desc` 默认为空；没有现成的分类信息，分类需要另做（见 §3.3）。

### 2.2 调用方式

AstrBot 的 `aiocqhttp` 适配器就是 NapCat 的反向 WebSocket 服务端，可以直接发动作：

```python
insts = context.platform_manager.get_insts()
client = insts[0].get_client()          # aiocqhttp 的 CQHttp 客户端
faces = await client.call_action("fetch_custom_face_detail", count=500)
```

踩点时用一个临时插件在 `on_astrbot_loaded` 里延迟 15 秒调用（等适配器握手），已删除。
正式方案不需要常驻插件：一次性脚本或部署脚本里调用即可。

### 2.3 素材情况

25 张的构成：20 张卡通（小狗为主，含 1 张猫狗贴贴）、3 张边牧照片、2 张猫照片
（猫眼特写、「狗狗祟祟」探头）。整体画风统一，与「温和、会自嘲、有点欠揍」的人设不冲突。

## 3. 最终方案（已实施）

### 3.1 本地包：一张图一个名字

`packs/qq-fav-001/` 的实际结构：

```text
packs/qq-fav-001/
├── manifest.json          # id / name / version / categories
├── memes_data.json        # 25 个名字 -> 描述
├── memes/<名字>/<md5>.<ext>   # 每个名字目录 1 张图
└── previews/              # 可选，WebUI 预览用
```

- 25 个目录、25 个名字，模型输出 `&&名字&&` 就能精确选到那一张。
- 名字用短中文（汉堡狗、笑脸狗、哭哭狗…），比长分类键更容易被模型原样复述。
- GIF 原样保留；本地文件发送已实测成功，不需要 base64。
- `registry.json` 已登记，`selection_rules.json` 的 default 已指向 `qq-fav-001`。

### 3.2 一轮出图：隐藏标记

1. meme_manager 把 `&&名字&&` 规则和 25 个名字写进 system prompt。
2. `qqbotstack_memechance` 在**所有 hook 之后**（priority `-100`）再补一段提醒 +
   两个真实示例（`今天好累 → &&毛巾狗&&`、`他走了 → 抱小鸡`），
   避免提醒被 guard 追加的世界书和接话上下文盖住。
   提醒明确写了「严肃或悲伤的对话里，想表达陪着、无奈、难过，也可以用安慰类的名字，
   不要用大笑的图」，否则模型会在悲伤剧情里一律不配图。
3. 模型在回复末尾输出 `&&名字&&`；meme_manager 的解析器把标记从正文剥掉，
   按名字找图，再按 `generation.emotion.probability` 决定是否真的发。
4. 不会额外调用模型，一轮完成；`max_memes_per_message=1`，一条回复最多一张。
5. 技术/调试类消息模型会自己选择不配图，这是预期行为。

### 3.3 频率

- 模型选中名字后，`generation.emotion.probability=50` 决定这一轮是否真的发图。
- 模型没选中、或门控没中时，`qqbotstack_memechance` 以 20% 概率从
  安慰/难过类（抱小鸡、猫狗贴、哭哭狗、哭脸狗、冒汗狗、趴问号、毛巾狗）
  随机兜底，`cooldown_sec=60`，避免严肃剧情里完全没有图。
- 两条路径互斥：meme_manager 已经安排配图时，兜底会跳过，一条回复最多一张。
- 想更低/更高只改这两个概率；`max_memes_per_message` 保持 1。

### 3.4 泄漏标签清理

模型在工具回合偶尔会把 `</rfl:parameter>` 这类闭合标签漏进正文。
`qqbotstack_memechance` 在发送前用正则 `</?[A-Za-z_][\w:.-]*(?:\s[^<>]*)?/?>`
清掉，并写日志 `stripped leaked tag`。这不是表情标记；表情标记 `&&名字&&`
由 meme_manager 处理。

### 3.5 实测

- 直接模型测试（完整真实 system prompt + 工具）：带工具 4/4 输出有效名字标记。
- 线上 17:40：`&&笑脸狗&&`、`&&流口水&&` 都被解析并从群里发出图片；
  正文本体只剩「转回来就好」「你这是损我呢 还是想请我吃东西」。
- 本地文件发送、标记剥离、概率门控都在同一条链路上验证过。

## 5. 风险与回退

| 风险 | 处理 |
|---|---|
| 收藏表情的 CDN 直链以后失效 | 25 张原图已本地留存；包内只引用本地文件 |
| 本地文件发送失败 | 打开 `send_image_as_base64`；仍失败则查 NapCat 日志 |
| 模型在技术/调试消息里不配图 | 预期行为；提醒只要求「适合配图时」才写标记 |
| 25 张偏少、容易重复 | 一图一名字，按概率抽取；后续从 `emoji-recv` 补充 |
| 模型漏出 `</rfl:parameter>` 一类标签 | `qqbotstack_memechance` 在发送前统一清理并记日志 |
| 想恢复官方包 | 从插件数据目录 `backup/` 复制回 `packs/` 并重新登记（不推荐，画风不符） |
| 重载插件期间断回复 | 安排在群里不活跃的时段重启，或接受约 10 秒空窗 |

## 6. 验收

已实测：

1. 直接模型测试（完整真实 system prompt + 工具）：带工具 4/4 输出有效名字标记。
2. 线上 17:40：`&&笑脸狗&&` → `去重后的最终表情列表: ['笑脸狗']`，正文只剩
   「转回来就好」，群里收到图片；紧接着 `&&流口水&&` 同样发出。
3. 本地文件发送可用：群历史里能查到机器人发出的 `image` 段。
4. 插件加载：`[memechance] enabled=False ... files=25 reminder=True names=True`。

日常验收：

1. 日志出现 `去重后的最终表情列表: ['<名字>']`，正文里看不到 `&&名字&&`。
2. 概率门控生效：`generation.emotion.probability=25`，约四分之一选中回合真正发图。
3. 工具回合漏出的 `</rfl:parameter>` 被清掉，正文干净。
